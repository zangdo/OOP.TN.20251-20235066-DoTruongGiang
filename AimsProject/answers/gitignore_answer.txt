Những đường dẫn .settings, bin, .classpath, .project này là các file và thư mục cấu hình riêng của môi trường phát triển (IDE) Eclipse. 
Chúng không phải là mã nguồn của dự án.
Lý do thêm .gitignore vào mã nguồn là:
    -Tránh xung đột: Mỗi lập trình viên có thể có cấu hình Eclipse khác nhau. Nếu commit các file này lên, đồng nghiệp khi kéo về có thể 
    gặp lỗi hoặc bị ghi đè cấu hình.
    -Giữ kho chứa sạch sẽ: Kho chứa Git chỉ nên chứa những thứ thiết yếu để xây dựng và chạy dự án. Các file được tạo tự động hoặc file 
    cấu hình cá nhân làm nhiễu lịch sử commit và tăng dung lượng kho chứa một cách không cần thiết.
    -Đảm bảo tính tái lập: Bất kỳ ai clone dự án về cũng có thể tự tạo ra các file cấu hình và file biên dịch của riêng họ chỉ từ mã nguồn. 
    Việc commit chúng lên là thừa thãi.
Nếu không thêm thì sẽ:
    -Xung đột liên tục: Mỗi khi thay đổi một cài đặt nhỏ trong Eclipse, Git sẽ báo rằng các file .settings, .project đã bị thay đổi. 
    Lập trình viên sẽ phải commit chúng. Khi đồng nghiệp git pull, họ có thể gặp conflict và phải giải quyết.
    -Kho chứa cồng kềnh: Thư mục bin/ có thể rất lớn. Commit nó lên làm kho chứa phình to, việc clone và pull sẽ chậm hơn.
Với IntelliJ IDEA và VSCode cần thêm gì vào .gitinore ? :
    IntelliJ IDEA: 
        .idea/: Đây là thư mục chính chứa tất cả các file cấu hình của IntelliJ cho project (tương đương với .settings, .project, .classpath
        của Eclipse gộp lại).
        *.iml: Các file module của IntelliJ.
        out/: Thư mục đầu ra mặc định chứa các file đã biên dịch (tương đương với bin/ của Eclipse).
    VSCode : 
        .vscode/: Thư mục chứa các cài đặt workspace riêng cho VSCode (ví dụ: file settings.json, launch.json để debug).
        Thư mục build của các công cụ như Maven hoặc Gradle (nếu dùng):
            target/ (đối với Maven)
            build/ (đối với Gradle)
            .gradle/

không xóa khỏi máy, bạn sẽ cần thực hiện những thao tác nào?
    Để Git "quên" file đó đi mà không xóa nó khỏi máy tính cần thực hiện lệnh sau:
        1. Đối với một file đơn lẻ (ví dụ: .project): git rm --cached .project.
        2. Đối với một thư mục (ví dụ: bin/): git rm -r --cached bin/.
    Giải thích lệnh:
        git rm: Lệnh để xóa file khỏi Git.
        --cached: Nó chỉ thị cho Git chỉ xóa file khỏi khu vực theo dõi (staging area/index), chứ không
        xóa file vật lý đang nằm trên ổ cứng.
        -r: (Recursive) Dùng khi muốn xóa một thư mục và tất cả nội dung bên trong nó.
    Quy trình đầy đủ:
        1.Thêm các file/thư mục cần bỏ qua vào file .gitignore và lưu lại.
            .settings/
            bin/
            .classpath
            .project
        2.Chạy lệnh git rm --cached cho từng file/thư mục đã lỡ commit.
            git rm -r --cached .settings/
            git rm -r --cached bin/
            git rm --cached .classpath
            git rm --cached .project
        3.Commit sự thay đổi này.
            git add .gitignore
            git commit -m "Stop tracking IDE files and build output".
        4.Đẩy.
            Git push.
